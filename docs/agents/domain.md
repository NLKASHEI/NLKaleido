# Domain documentation

Use a single-context layout: root `GLOSSARY.md`, repository-wide `docs/adr/`, and investigations in `docs/research/`.

- Read the glossary before naming modules or writing tickets.
- Read applicable ADRs before modifying storage, events, prompt injection, or memory retrieval.
- An ADR is a recorded decision, not proof that its implementation exists.
- If a new design contradicts an ADR, identify the conflict and supersede the ADR explicitly.
- Keep reference-source observations in `docs/research/`; do not silently promote third-party behavior into a local requirement.
