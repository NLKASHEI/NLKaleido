# 万花筒 · NLKaleido

**v0.11.0 — 破坏性重构版（SillyTavern 扩展）**

万花筒面向角色卡作者和玩家提供一套简单易用、由 LLM 辅助更新的变量系统。作者定义字段、规则、频率与显示权限；玩家只看简洁状态栏。变量更新采用分字段调度、中文 BM25F 证据检索、结构化提案、本地契约校验和聊天存档读回确认。

## 安装

在 SillyTavern 的 **扩展管理 → 安装扩展** 中使用：

```text
https://github.com/NLKASHEI/NLKaleido
```

扩展入口为 `manifest.json` 指向的 `dist/index.js`。这是可安装的 Git 仓库，不需要安装源码工具链。已经从本仓库安装旧版的用户可以通过扩展管理器更新后刷新酒馆。

不要同时安装之前的独立 Alpha 预览扩展，否则可能出现两个按钮或重复监听。

## 使用流程

1. 在**单人角色聊天**内点击右下角的 **✦ 万花筒·新版工作台**。
2. 编辑变量契约，包括字段类型、默认值、自然语言变化规则、依赖、玩家可见性和每几轮自动检查一次。
3. 点击 **保存**，再明确点击 **绑定当前聊天（实验）**。该动作初始化当前聊天的新版契约。
4. 点击 **自动更新设置**，确认模型调用可能消耗 Token 后手动开启。**自动更新默认关闭**。
5. 玩家可以点击 **✦ 角色状态** 打开简易只读面板。

正常角色回复结束时，已启用的变量系统可以调用酒馆当前选定的模型提出更新建议；BM25F 用于检索证据，**最终写入必须通过本地字段与数值约束**。作者还能规定单次最大数值变化和不同变量的检查间隔。

## 破坏性更新声明

**v0.11.0 直接替换 v0.10.0 的旧运行时，不保证向后兼容。**

- 旧版的记忆、剧情编排、检定、MVU 迁移等附加模块，当前版本尚未重做。
- 旧版脚本 API / 原有配置不会自动兼容；旧数据不会被自动迁移到新变量契约。
- 新版使用聊天内独立的 `chatMetadata.nlkaleido_update_runtime_v1` 保存契约、状态、审计和更新进度。
- 当前仅对单人聊天提供可验证写入；群聊仍不支持自动写入。
- 旧聊天被编辑、Swipe 或重生成时可能因历史指纹变化而暂停更新，这是防止误写的安全机制。
- 自动更新可能额外调用模型并产生费用；是否开启由作者决定。

## 开发与构建

Node.js 22+：

```bash
npm install
npm run check
npm run ui:dev
npm run ui:extension
```

正式发布的 `dist/index.js` 由 CI 编译生成，并与 `manifest.json` 一起提交到 Git 仓库。浏览器预览页：作者端 `/index.html`，玩家端 `/player.html`（通过开发服务器访问）。

## 质量边界

CI 能检查 TypeScript、自动化测试及打包完整性，但**不能代替你的真实 SillyTavern 环境验收**。尤其在自动更新与模型调用场景，请先使用测试聊天，核实生成中止、Swipe、聊天切换、保存读回和玩家变量权限。

技术与研究说明：[变量更新引擎](docs/reconstruction/variable-update-engine.md) · [酒馆运行时](docs/reconstruction/st-update-runtime.md) · [发布审查](docs/reconstruction/st-release-audit-20261012.md)。
